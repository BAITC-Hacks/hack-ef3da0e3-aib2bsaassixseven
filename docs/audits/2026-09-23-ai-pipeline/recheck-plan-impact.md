# Повторная проверка: влияние новых изменений на план

Дата: 2026-09-23. Проверены текущие `review.py`, `models.py`, `runtime.py`, `__main__.py`, `ML_README.md`, `test_ml_reviewed_corrections.py`; дополнительно просмотрены затронутые места `abstraction.py` и `compare.py`. Production и прежние отчеты не изменялись. Проверку live Brev выполняет основной агент.

Граница снимков: первоначальное чтение и три проверки ниже относились к версии с insertions. При финальном перечитывании `review.py` в тот же день уже содержит `ReviewedReplacement`; описания correction contract ниже обновлены по этому коду. Собственный повторный прогон replacements здесь не выполнялся; финальный набор проверяет независимый верификатор.

**Рекомендация:** сохранить новый механизм исправлений, закрыть оставшиеся ошибки семантики по результатам отдельной повторной проверки и следующим небольшим изменением сделать сохранение исходного/исправленного транскриптов и replay надежными. Полную миграцию на event ledger и замену моделей пока не ставить раньше этих работ.

## Что уже покрыто

| Прежняя рекомендация | Текущая реализация | Статус |
|---|---|---|
| Аудируемые ручные поправки до extraction | `--reviewed-corrections` передает manifest; проверяется SHA исходного audio, интервалы, уникальные `rNNNNN`; текущий код применяет replacements, затем insertions до extraction | Покрыто для вставок и ограниченных замен текста; замена требует ровно одну полностью входящую в заданное окно utterance с `old_text`, меняет первое вхождение на `new_text` и записывает `replaced_utterance_ids` |
| Не угадывать speaker по имени | Вставке принудительно присваивается `speaker_id=None`, replacement сохраняет ID, timestamps и speaker исходной utterance; extra fields запрещены | Correction contract не назначает новый speaker; дальнейшие owner heuristics остаются отдельным механизмом |
| Зафиксировать code provenance | Добавлен `pipeline_code_sha256` всех Python-файлов пакета; сохраняются manifest SHA и IDs, копия manifest | Частично покрыто; пока нет полного run config, dependency lock hash, stage manifest и снимка исходного ASR |
| Исправить salvage resurrection | В `abstraction.py` теперь `extend(getattr(single, section))` вместо добавления исходного item | Конкретная причина устранена в коде; общий статус regression suite подтверждают finder/verifier |

| Проверять относительный deadline при `due_date=null` | `compare.py` теперь сравнивает нормализованный `due_text`, если обе даты null и поле включено в reference | Частично покрыто; gold должен содержать это поле, сравнение пока текстовое |

В manifest примера явно сказано: фраза с именем восстановлена по расширенному audio window, написание сверено с пользователем. Это прозрачная **ручная коррекция входа**, а не улучшение ASR-модели или независимый новый quality benchmark. Hash доказывает, к какому файлу относится manifest; он не доказывает правильность прослушивания. Строка `review_note` сохраняет объяснение, но не фиксирует структурированно проверяющего и время проверки.

## Что осталось и как скорректировать очередность

1. **Stage persistence по-прежнему отсутствует.** `runtime.py` сначала выполняет Qwen, затем создает output directory и пишет transcript. Ошибка JSON/OOM по-прежнему теряет готовую ASR-работу. Сохранять неизменный `transcript.raw.json` сразу после ASR, correction manifest и `transcript.reviewed.json` после validation, затем extraction. Отмечать stage status и завершать run атомарно; успешный прошлый run не перезаписывать частично. Gate: падение после ASR оставляет читаемый raw transcript; падение LLM не уничтожает reviewed transcript; resume не запускает ASR снова.
2. **Provenance требует снимка на старте.** Manifest сейчас читается и хешируется перед LLM, но копируется с исходного пути после LLM. Если файл меняется во время inference, итоговая копия может расходиться с записанным hash. Сохранить ровно прочитанные bytes до extraction и использовать этот snapshot. Аналогично code hash в конце описывает файлы на диске в конце, а не обязательно выполнявшуюся версию при concurrent edits; фиксировать code/config до запуска. Gate: изменение исходного manifest после загрузки не меняет snapshot/hash текущего run.
3. **Довести контракт overlay.** `insertions` и `replacements` теперь явно разделены; replacement сохраняет исходный ID и имеет проверку единственного подходящего utterance. При этом перекрывающиеся вставки все еще могут дублировать распознанный текст, а replacement выбирает первое вхождение `old_text` внутри найденной utterance. Не запрещать все overlap: показывать его на review, сохранять raw/corrected результаты и уточнить поведение нескольких совпадений внутри одной utterance, пересекающихся замен и повторного применения. Gate: повтор одной и той же поправки идемпотентен либо явно отвергнут; идентичная фраза не превращается в два поручения; исправление остается привязанным к исходным интервалам. Наличие replacements делает сохранение исходного текста еще важнее.
4. **Replay в тот же output требует защиты.** Статическое наблюдение: если `--reviewed-corrections` указывает на уже сохраненный `output_dir/reviewed_corrections.json`, финальный `shutil.copyfile` получает один файл как source и destination. Проверить этот сценарий отдельным regression и использовать snapshot + отдельный run directory/явную политику overwrite. Этот риск не следует путать с ошибкой семантики модели.
5. **Семантика, budget и evaluation остаются отдельными задачами.** `Task` по-прежнему имеет один quote и список source IDs; нет field evidence/event history. Chunking повторно использует original utterance ID для fragments и ограничивает chars, не полный token prompt; reconciliation растет со state. `compare.py` по-прежнему использует greedy string matching; добавленное сравнение `due_text` работает только при обеих null dates и наличии поля в gold, поэтому разметку нужно расширить, а semantic task matching проверить отдельно. Эти рекомендации прежнего плана остаются актуальны. Narrow date/cancellation fixes нужно перепроверять соседними случаями, а не объявлять весь класс ошибок закрытым.

## Ближайший проверяемый результат

Сделать одну небольшую итерацию надежности review/replay: immutable raw+reviewed artifacts, snapshot manifest bytes, stage status, запись config/lock hash и возможность extraction из сохраненного transcript. Добавить acceptance cases: hash mismatch, duplicate IDs, invalid/out-of-bounds intervals, input manifest mutation, same-file replay, LLM failure и повторный запуск. Затем выполнить paired comparison **raw pipeline / assisted pipeline** на неизменном audio: число исправленных spans, ручное время, owner/date/task corrections, остаточные ошибки. Указывать вклад человека отдельно; не включать corrected transcript в отчет об автоматическом ASR WER.

После этого выбирать между локальными моделями на gold transcript и end-to-end labeled audio, как предложено раньше. Новый manifest не делает текущие две подогнанные встречи независимым holdout. Большой event ledger остается направлением для накопившихся update/cancel cases, а не обязательным условием использования полезной ручной поправки.

## Проверка и ограничения

На первоначальном снимке с insertions обычный запуск `pytest tests/test_ml_reviewed_corrections.py tests/test_ml_runtime.py -q` остановился на Windows `PermissionError` при работе с временными каталогами; это не падение assertion продукта. Два существовавших pure correction tests выполнены напрямую и прошли. Существовавший runtime integration test прошел при прямом вызове с заменой только `TemporaryDirectory` на доступный workspace directory; модели уже замоканы самим тестом. Это подтверждает wiring и запись manifest того снимка, не новые replacements, реальный inference или качество распознавания.

Broad web research не повторялся: новых model/API утверждений этот recheck не делает. Проверенные ранее источники и критерии модельного сравнения остаются в `researched-solutions.md`. Новые риски snapshot/replay отправлены независимому верификатору для challenge.
